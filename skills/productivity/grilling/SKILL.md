# grilling

## Purpose

Stress-test a plan, decision, or idea by asking about it, one question at a time, before anyone acts on it.
The assumption that would have caused a rewrite later is cheaper to catch now, in conversation, than after the work is done.

## When to use

The user says "grill me" or "stress-test this," or otherwise asks to have their thinking checked before committing to it.

## Process

1. Split what you'd want to know into facts and decisions. A fact is answerable by reading the filesystem, the code, or existing docs - go find it yourself, don't ask. A decision is something only the user can make; that's what you actually ask about.
2. Ask one decision at a time. Wait for the answer before asking the next. Several questions at once make it hard to think clearly about any of them.
3. Give a recommended answer with every question, so the user is reacting to a concrete proposal instead of starting from nothing.
4. Let each answer decide what you ask next: a decision tree, not a fixed checklist. If an earlier answer makes a later question moot, drop it.
5. Don't act on the plan, decision, or idea until a shared understanding is confirmed. Summarize where things landed and get an explicit yes before moving on.

## Related

`to-spec` runs a similar one-at-a-time interview, but ends in a written spec document for a feature.
`grilling` is lighter: no document, works on any plan or decision, not just features, and is meant to be quick.
